# V2 教育排课数据迁移策略

## 决策

V2 不自动迁移旧到店服务数据。旧预约中的服务人员、项目和客户字段无法可靠映射为教师授课资格、课程年级、校区服务关系和学生信息，静默转换会制造错误排课数据。

## 本地开发

1. 使用独立数据库 `data/education_scheduling.db`。
2. 在 `.env` 设置 `AUTO_INIT_DB=true` 创建教育 Schema。
3. 仅需要演示数据时设置 `SEED_DEMO_DATA=true`。
4. 旧数据库保留为只读备份，不覆盖、不复用文件名。

## 生产部署

1. 设置 `AUTO_INIT_DB=false`、`SEED_DEMO_DATA=false`。
2. 在发布窗口中用受控、版本化迁移创建 Schema。
3. 如需导入真实数据，先完成人工字段映射、去重和时区校验，再通过独立 ETL 导入。
4. 校验教师资格、教师校区、学生必填和课程时间后再开放写流量。

SQLite V1 在每个连接启用外键，并用 `BEGIN IMMEDIATE` 串行化排课创建。多实例生产环境应使用 PostgreSQL，并为教师和学生的有效课程时间范围增加排他约束。
